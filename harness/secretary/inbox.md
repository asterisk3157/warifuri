# 受信箱の整理(inbox)

週に1回、プロフィールごとの受信箱を整理します(原則22)。受信箱には、エージェントがタスクを閉じるときに残した気づきが、ナレッジになる前の形でたまっています。気づきには判断や推定が混ざるので、そのままナレッジにはしません。

## 1. 読む

1. `proposals` で了承された案を読み、先に行って `proposal_done` を付けます。
2. `autonomy` を読み、`tidy_inbox`、`add_knowledge`、`split_knowledge`、`mark_stale_knowledge` の自律度を確かめます。
3. `profile` で、プロフィールの名前を集めます。
4. プロフィールごとに `context` を `profile` で読みます。`inbox` が受信箱、`knowledge` がいまのナレッジ、`people` がその領域の人の一覧です。受信箱が空で、knowledge.md も分ける目安(`split_knowledge` の一覧の `over`)を超えていないプロフィールは飛ばします。

## 2. 分ける

受信箱の1件ごとに、次のどれに当たるかを決めます。

- ナレッジに入れるとよい: 手順、決まりのように、次の作業で効くもの。どの文に直して、knowledge.md のどこに入れるかの案を作ります。
- 人のこと: 相手の名前、立場、好みのように、人についてのもの。`sort_inbox` の `to: "people"` で、そのプロフィールの「人」に移します。だれのことかは `person` に id を渡して決めます(渡さなければ、文の頭の名前で決まり、決まらなければ「だれのことか決まっていない」に入ります)。まだいない人なら、先に `person` で作ります。受信箱のことはエージェントの読み取りなので、列や `items` に書くときは `unverified: true` を付けて未確認にします(メモは未確認のまま入ります)。本人の言葉と分かるものだけ、確かな値で書き、同じ列の未確認の値を置き換えます。人のことは、自律度に関係なく、聞かずに書いてかまいません。すでに「人」にあるものは書きません。knowledge.md に人のことが混ざっていれば、`note` に `people: true` を付けて「人」に写します。
- すでにある: knowledge.md にある内容と重なるもの。どの行と重なるかを書きます。
- 古くなった: いまのナレッジや、あとの気づきと食い違うもの。いつまで有効だったかを書き足す案を作ります。
- 確かめが要る: 推定が混ざっていて、本人に聞かないと決められないもの。1件ずつ、答えやすい問いにします(原則16)。
- 領域の外: このプロフィールではなく、リポジトリの `AGENTS.md` や、ハーネスの全体の指示書に書くべきもの。どこに書くとよいかを本人に知らせます。warifuri の外の文書は、秘書は書き換えません。
- 要らない: その場かぎりで、残す意味のないもの。

knowledge.md がおよそ200行を超えていたら、話題ごとに `knowledge/` に分ける案(`split_knowledge`)も作ります。

## 3. 行う

受信箱とナレッジは、次のツールで書き換えます。どれも、`moves` や `marks` を渡さずに呼ぶと、項目を id つきで一覧するだけです。一覧で返った id をそのまま渡します。

| すること | ツール | 自律度の種類 |
|---|---|---|
| ナレッジに入れる、重なるものを1つにまとめる | `sort_inbox` の `to: "knowledge"`(または `knowledge/<話題>.md`)。まとめるときは、まとめた文を `text` に | `add_knowledge` |
| 「人」に入れる | `sort_inbox` の `to: "people"` | 聞かずに行う(上の「人のこと」) |
| すでにある、要らない、領域の外を受信箱から外す | `sort_inbox` の `to: "drop"` と `reason` | `tidy_inbox` |
| 古くなったナレッジに、いつまで有効だったかを書き足す | `mark_stale` | `mark_stale_knowledge` |
| knowledge.md を話題ごとに分ける | `split_knowledge`(一覧の `over` が true のとき) | `split_knowledge` |

- 自律度が `act_then_tell` の種類は、そのまま行い、報告に何をしたかを書きます。
- 古い印(`mark_stale_knowledge`)は、自律度にかかわらず、1件ずつ案にして聞くことはしません。新しい項目が置き換えた、書かれた期限が過ぎた、のように古いのがはっきりしたものだけ `mark_stale` で印を付け、報告に書きます。はっきりしないものは、そのままにします。
- ほかの `ask` の種類は行わず、`propose` で1件ずつ案にします。案の本文には、どの項目(受信箱の文をそのまま)をどうするかを書きます。了承された案は、次の受信箱の整理の初めに `proposals` で読み、行ってから `proposal_done` を付けます。
- 確かめが要るものは受信箱に残し、`propose` で本人に聞きます。本人が確かめたものだけ、`checked: true` を付けて入れます。それ以外は「未確認」のまま入ります。
- 領域の外のものは、どこに書くとよいかを報告に書いてから、受信箱から外します。
- 1回の呼び出しに1つでも問題があれば、何も書かずに断られます。直して呼び直します。

`context` に `people_md`(前の形の people.md)が残っているプロフィールがあれば、「people.md を人に取り込んでよいか」を、決めてほしいこととして報告に書きます。取り込みは、本人が会話で「いい」と言ってから、会話の秘書が行います。

`report` を `kind: "inbox"` で書きます。プロフィールごとに見出しを立て、行ったことと案にしたことを、上の分け方ごとに件数と中身で並べます。確かめが要るものは、決めてほしいこととして先頭に置きます。

どのプロフィールの受信箱も空で、分けるナレッジもなければ、`report` を呼びません。
