# 受信箱の整理(inbox)

週に1回、プロフィールごとの受信箱を整理します(原則22)。受信箱には、エージェントがタスクを閉じるときに残した気づきが、ナレッジになる前の形でたまっています。気づきには判断や推定が混ざるので、そのままナレッジにはしません。

## 1. 読む

1. `autonomy` を読み、`tidy_inbox`、`add_knowledge`、`split_knowledge`、`mark_stale_knowledge` の自律度を確かめます。
2. `places` と `board` から、プロフィールの名前を集めます。
3. プロフィールごとに `context` を `profile` で読みます。`inbox` が受信箱、`knowledge` と `people` がいまのナレッジです。受信箱が空のプロフィールは飛ばします。

## 2. 分ける

受信箱の1件ごとに、次のどれに当たるかを決めます。

- ナレッジに入れるとよい: 手順、相手の好み、決まりのように、次の作業で効くもの。どの文に直して、knowledge.md のどこに入れるかの案を作ります。
- すでにある: knowledge.md にある内容と重なるもの。どの行と重なるかを書きます。
- 古くなった: いまのナレッジや、あとの気づきと食い違うもの。いつまで有効だったかを書き足す案を作ります。
- 確かめが要る: 推定が混ざっていて、本人に聞かないと決められないもの。1件ずつ、答えやすい問いにします(原則16)。
- 領域の外: このプロフィールではなく、リポジトリの `AGENTS.md` や、ハーネスの全体の指示書に書くべきもの。どこに書くとよいかを本人に知らせます。warifuri の外の文書は、秘書は書き換えません。
- 要らない: その場かぎりで、残す意味のないもの。

knowledge.md がおよそ200行を超えていたら、話題ごとに `knowledge/` に分ける案(`split_knowledge`)も作ります。

## 3. 書く

いまの warifuri のツールでは、秘書が受信箱から項目を消したり、knowledge.md の行を書き換えたりはできません(`note` は書き足すだけで、`kind: "human"` は本人の言葉の印を付けるので、エージェントの気づきには使いません)。そのため、自律度が `act_then_tell` の種類でも、この仕事では案を書くだけにします。動かすツールが足されたら、自律度に従ってそのツールで行います。

`report` を `kind: "inbox"` で書きます。プロフィールごとに見出しを立て、上の分け方ごとに件数と中身を並べます。確かめが要るものは、決めてほしいこととして先頭に置きます。

どのプロフィールの受信箱も空なら、`report` を呼びません。
