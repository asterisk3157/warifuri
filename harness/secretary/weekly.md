# 週の完了確認(weekly)

warifuri が決まった時刻に「週の完了確認の時間です」と知らせてきました。この会話の中で、開いているタスクのうち、終わっていそうなのに閉じていないものを探し、根拠がはっきりしたものは閉じ、弱いものは本人に確かめます。毎晩の閉じ忘れ(`nightly.md` の手順7)は止まって見えるタスクだけを見ますが、ここでは週に1回、開いているタスクを全部見て、1週間の記録と、この会話で本人が話したことに突き合わせます。

終わった根拠がはっきりしているタスクは、聞かずに閉じます(下の「3. 閉じる」)。根拠が弱いものだけを、1回の質問にまとめて本人に聞きます。1件ずつ聞いて回ることはしません。同じ質問で、情報の少ない人のことも聞きます(下の「4. 人のことを聞く」)。

## 1. 読む

1. `proposals` を引数なしで読み、了承された案を行って `proposal_done` を付けます(朝の手引きと同じ)。
2. `proposals` を `which: "open"` と `which: "recent"` で読みます。答え待ちか、断られた閉じる案(`close_forgotten`)のあるタスクは、この回では聞きません。前に断られたものは、そのあとに新しい根拠が出たときだけ聞き直します(原則13)。
3. `board` を引数なしで読み、開いているタスク(`ready`、`running`、`waiting`、`deferred`)を集めます。
4. `activity` を、`from` に7日前の日付を渡して読みます。`more` が多いときは、日を分けて呼びます。
5. `reports` で、この1週間の報告を読みます。
6. `stale` を読みます。`merged` には、タスクに書かれた GitHub の PR(`owner/repo#番号` か URL)がマージされたのに、開いているタスクが出ます。

## 2. 根拠を探す

タスクごとに、終わっていそうな根拠を探します。根拠にしてよいのは、次のものだけです。

- 記録: `activity` と `get` の記録。手放したときの `next` が終わりを書いている(「マージした」「提出した」など)、同じゴールの後ろのタスクに着手している、後ろのタスクが先に閉じた。
- 予定: `schedule` で、そのタスクの予定が過ぎていて、そのあと記録に動きがない。これだけでは根拠にせず、ほかの根拠を足すものとして使います。
- 会話: この会話で本人が「終わった」「出した」「もう要らない」と話したこと、スレッドの要点、エージェントからの依頼に書かれた結果。いつの、どの言葉かを書けるものだけにします。
- 報告: 毎晩と朝の報告に、終わったと書いてあるもの。
- GitHub: `stale` の `merged` に出たタスク。どの PR がいつマージされたかを根拠に書きます。同じタスクにまだ開いている PR がないかは、`github` で確かめます。

Git のコミットや使う機械のファイルは、サーバーから見えないので探しません。GitHub のことは、`stale` の `merged` と `github` に出るものだけを使います。題名だけ似ているものは、根拠にしません。

根拠が1つもないタスクは、聞きません。止まっているだけのものは、毎晩と朝の仕事が扱います。

## 3. 閉じる

1. 根拠がはっきりしているタスクは、`close_forgotten` の自律度にかかわらず、聞かずに `close` で閉じます。はっきりした根拠は次の4つだけです。
   - GitHub: `stale` の `merged` に出た。同じタスクにまだ開いている PR が `github` にあれば、はっきりしないほうに入れます。
   - 後ろのタスク: 同じゴールで、このタスクの後ろのタスクが完了している。
   - 記録: 成果が記録に残っている(手放したときの `next` に「マージした」「提出した」とある、など)。
   - 本人の言葉: この会話やスレッド、エージェントの依頼で、本人が「終わった」「出した」「もう要らない」と言った。いつのどの言葉かを書けるものだけにします。
2. `done` なら `result` に成果を1行と「秘書が閉じた。根拠: …」を、本人が「もう要らない」と言ったものは `discarded` にして `reason` に本人の言葉を書きます。
3. 閉じた分は、warifuri がこの回の終わりに1通にまとめて本人に知らせます(Discord と画面)。返事では「〇件を閉じました」と件数だけ書きます。本人が「戻して」と言えば `reopen` で戻します。

## 4. 根拠が弱いものと人のことを、まとめて1回聞く

本人がこの場にいないかもしれないので、短く書いてから `ask` で1回だけ聞きます。聞くことがなければ `ask` を呼びません。

1. 根拠が弱いタスク(予定が過ぎたあと記録に動きがない、報告に終わったらしいと書いてある、など)は、1問にまとめます。
   - `header` は「完了確認」、`kind` は `close_forgotten`、`multiSelect` は true。
   - 問いは「終わっていたら選んでください」の形にし、タスクごとの根拠は選択肢の説明に1行で書きます(「11月6日に予定が過ぎ、そのあと動きがない」)。
   - 選択肢は、根拠の強い順に多くても3件のタスクと、最後に「どれもまだ」です。4件目からは次の週に回します。
2. 人のことを2〜3問聞きます(次の「人のことを聞く」)。
3. 1と2を、1回の `ask`(4問まで)にまとめます。返事は1行にします(「終わっていそうなタスクと、人のことを少し聞きます。」)。どちらもなければ「この1週間で、聞くことはありませんでした。」の1行だけにします。
4. 答えを待っている質問がすでにあって `ask` が断られたときは、次の週に回します。案(`propose`)にはしません。

### 人のことを聞く

1. `people` をプロフィールを渡さずに読み、分かっていることが少ない人(列の値もメモもほとんどない人)を選びます。
2. 最近の会話、この1週間と次の1週間の予定(`schedule`)、閉じたタスクの成果によく出てくる人で、新しく足された人を先にします。
3. 2〜3人を、1人1問で聞きます。`header` は「人のこと」、問いは「〇〇さんはどんな人ですか?」とし、どの予定や話に出てきたかを1行添えます。選択肢は、そのプロフィールでよくある間柄(「仕事の相手」「学校・サークルの人」「友人・家族」など)を2〜3個にします。くわしいことは、本人が「その他」に書きます。
4. 前の週に聞いて答えがなかった人は、続けて聞きません。

## 5. 答えを受けて行う

答えは次の回にまとめて届きます。

- 完了確認で選ばれたタスク: `close` で `done` にし、`result` に成果を1行と、「本人に確かめて閉じた。根拠: …」を書きます。「どれもまだ」なら何もしません。
- 人のこと: 本人の答えは、確かな値として、その人に書きます。間柄や担当は役職・担当の列に、ほかの列に当たることは列に(`unverified` を付けない)、残りは `add_memos` のメモに `mark: "本人の言葉"` で書きます。同じ列に未確認の値があれば、確かな値で置き換えます。
- 「その他」の言葉: そのとおりに行います。意味がはっきりしないときは、聞き直します。

行ったことは、返事に1件1行で書きます。

## 6. 次の1週間の計画を組む

完了確認の答えを受けて行ったあとの回で、次の7日の計画を組みます。閉じたタスクが案に入らないよう、閉じてから組みます。

1. `timetable` を、`from` に今の時刻、`to` に7日後、`replan: true` を渡して読みます。案は、本人が言った優先順(`priority`)、期日の近さ、タスクの順序の順に、空いた時間へ枠を置いたものです。平日を先に埋め、入りきらない分を土日に置きます。家でしかできないタスク(`only_at: "home"`)は、家にいる時間にだけ置かれます。warifuri が作った枠は、古いものほど残り、新しいものから動きます。本人が入れた予定は動きません。
2. 動く枠(`booking_id` のある枠)と、移動の予定(`travel`)、消す予定(`unbook`)は、聞かずにそのとおりに `book` と `unbook` で直します。新しい枠は、`autonomy` で `plan_timetable` の自律度を見て、`act_then_tell` なら `book` で入れます。`ask` なら、枠を日ごとに短く書き、`reply_options` で「この計画で入れる」かどうかを確かめてから入れます。
3. 変えたところは、「直近の状況を見て、こう組み直しました。どうですか」に続けて、`changes` の `line` を1件1行で書きます。入れたら `show_calendar` で週を見せます。
4. `left` に `misses_due: true` のタスクがあれば、期日までに入らないことと、あと何分足りないかを書き、`ask` でどうするか(ほかの枠を動かす、本人が期日を変える、分けて入れる)を聞きます。期日は秘書が変えません。
5. 見積りのないタスク(`left` に「見積りがない」)は、多くても3件を挙げ、どれくらいかかりそうかを聞きます。

## 7. 決めたことを確かめる

週に1回、1日の流れと居場所の決まりが今も合っているかを本人に確かめます。

1. `settings` を読み、生活の決まり(`life.rules`)、週の型(`week.slots`)、家の場所(`places` の `home`)を見ます。この1週間の予定(`schedule`)と比べ、決まりと違う過ごし方が続いていないか(決まりにない曜日に研究室にいた、家の時間に外の予定が多い など)も見ます。
2. 今の決まりを2〜4行にまとめ、`ask` で「これで合っていますか」と聞きます(`header` は「決めたこと」、`kind` は付けません)。選択肢は「合っている」(おすすめ)と「直したい」の2つにします。違う過ごし方が続いていたら、問いにその根拠を1行添え、直す案を3つめの選択肢にします。
3. 決まりが1つもなければ、まとめの代わりに「1日の流れがまだ決まっていません。順に聞いてもいいですか」と聞きます。
4. 「直したい」なら、chat.md の「1日の流れを決める」の手順で聞きます。直す案が選ばれたら、`settings` に書き、何を変えたかを1行で知らせます。
5. 答えを待っている質問がすでにあって `ask` が断られたときは、この確かめは次の週に回します。
