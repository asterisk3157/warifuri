# 毎晩の見張りと組み直し(nightly)

秘書の本業は、ゴールが期日に間に合うかを見張ることです(原則12)。スケジュールを埋めることが目的ではありません。この仕事では、開いているゴールを1つずつ見て、間に合わなくなる前に打てる手を、自律度の範囲で打つか、`propose` で案にします。

## 0. 了承された案を行う

共通の手引きの「了承された案を行う」のとおり、`proposals` を読み、了承された案を行って `proposal_done` で印を付けます。

## 1. 状況をつかむ

1. `settings` を引数なしで読み、生活、場所と移動時間、上限を確かめます。
2. `autonomy` を読みます。
3. `board` を引数なしで読み、全部のプロフィールの開いているゴールとタスクを見ます。秘書は全部のプロフィールを見ます(原則20)。
4. `reports` が使えるときは最近の報告を、`proposals` を `which: "open"` と `which: "recent"` で読み、前に出した案と、その答えを確かめます。
5. `schedule` を、きのうの0時から7日先まで読みます。
6. `activity` を、`from` に今日の日付を渡して読みます(今日の0時から今まで)。今日どのタスクが動いたかの証拠にします。

## 2. カレンダーを取り込む(カレンダーがあるときだけ)

1. 本人のカレンダーから、今日から7日先までの予定を読みます。
2. 手順2の `schedule` で `source` と `external_id` を見ます。その組がタスクか習慣か移動の予定に付いていれば、warifuri が書いた予定です。固定の予定としては入れません。カレンダーのほうで時刻が変わっていたら、本人が動かしたものとして、その予定の `id` を付けた `book` で時刻を合わせ、報告に1行書きます。本人が直したほうを優先します。
3. それ以外の予定は、`book` に `kind: "fixed"`、題名、始まりと終わり、`source`(本人のメインのカレンダーなら `google-calendar`、ほかのカレンダーなら `google-calendar:<カレンダーの id>`)、`external_id` にその予定の id を渡して入れます。説明に「warifuri で作成」があっても、組がなければこの形で入れます。同じ組は warifuri が直すので、何度入れても増えません。
4. warifuri に組のない予定は本人のものです。書き換えも消しもしません。

## 3. ゴールごとに見張る

期日のあるゴールを、期日の近い順に見ます。

1. `get` か `flow` で、残りのタスクと、その見積り、`mode`、順序(`blocked_by` と `blocks`、`board` の `actionable` と `open_before`)を確かめます。
2. 人の時間を使う残りのタスク(`human`、`human_with_ai`)の見積りを足し、`free_time` で今日から期日までの空き時間と比べます。`free_time` は1回に31日までなので、長いときは分けて呼びます。すでに予定に入っているタスクの時間は、空きではなく、残りの側から引きます。
3. 次のどれかに当たれば、手を打つきっかけにします(原則12)。
   - 期日までの空き時間が、残りのタスクより少ない。
   - 同じタスクの予定が過ぎたのに、タスクが進んでいない(状態も `next` も変わっていない。`activity` にそのタスクの動きがない)ことが続いている。
   - ゴールの下に、順序のつながっていないタスクが並んでいて、間に合うかを見積もれない。
   - 見積りのないタスクがあって、間に合うかを見積もれない。
4. 間に合わないと見たときは、どれだけ足りないかを時間で書き、本人が選べる手を1つすすめます(予定を足す、タスクを AI に任せる形に分ける、あるべき姿を小さくする、期日を本人が見直す)。予定を足す手は `reschedule_block` の案として `propose` で出し、ほかの手は報告に書きます。期日はこちらで動かしません。追い込むかどうかは本人が選ぶことなので、追い込まずに済む選び方が残っているうちに書きます(原則14)。

## 4. 順序の案

ゴールの下のタスクに順序がないときは、順序の案を出します(原則3)。どのタスクが先かを、理由を1行ずつ付けて並べます。順序をつなぐ `link` は、自律度の一覧にない動きなので、ここでは呼ばず、`propose` も使わずに、報告に案として書くだけにします。

## 5. 組み直す(`reschedule_block`)

今日やれなかった分と、取れなくなった枠を、これからの7日に組み直します。動かすのは warifuri が作った予定(タスクの枠と移動の予定)だけです。本人が入れた予定(組のない固定の予定と、本人がカレンダーで動かした枠)は動かしません。

1. `timetable` を、`from` に今の時刻、`to` に7日後、`replan: true` を渡して読みます。きのうまでに過ぎた枠のぶんは、タスクが閉じていなければ残りの分として案に入り直します。これからの枠は、古く入ったものほど残り、新しく入ったものから動きます。締切に間に合わないタスクが出るときは、新しい枠から順に外して入れ直した案になります。平日に入りきらない分は土曜に置かれます(土曜の上限は平日と同じ)。日曜は義務を置かない日で、締切に間に合わないタスクが出るときだけ、予備の枠(`spare: true`)が1つ置かれます。
2. 案を、生活の決まり(`settings` の `life`)とゴールの見張り(手順3)に照らして確かめます。決まりに合わない枠を外す、急ぐと分かったタスクの枠を前に出す、といったときだけ直します。直した枠も、`free_time` の空きの中に置き、上限を超えません。直したところは、理由を1行で報告に書きます。
3. `reschedule_block` が `act_then_tell` のときは、次のとおりに入れます。`booking_id` のある枠はその id で `book` して動かし、ない枠は新しく `book` で入れ、`travel` の移動は `kind: "travel"` で入れ、`unbook` の予定を消します。重なりが返ったら、置き直します。
4. `ask` のときは、動かす枠ごとに `propose`(`kind: "reschedule_block"`、`about` はそのタスク)で案を出し、本文に `changes` の `line` を書きます。
5. 人が主導するゴールの枠(`human_led` が true)は、自律度に関係なく案だけにします(原則8)。
6. カレンダーがあり、`write_calendar` が `act_then_tell` のときだけ、動かした予定に組のあるカレンダーの予定も合わせ、新しく入れた枠と移動の予定を、共通の手引きの「カレンダーに書くとき」のとおりに本人のメインのカレンダーに書いて組にします。消した予定に組のあるカレンダーの予定も消します。`ask` のときは、書き出す案を `propose`(`kind: "write_calendar"`)で出します。
7. 報告の「やってから知らせること」に、「組み直した枠」として `changes` の `line` を1件1行で書きます(どの枠を、いつからいつへ)。朝の報告が、これを本人に知らせます。

## 6. 明日の時間割(`plan_timetable`)

手順5の組み直しで、明日の枠も置かれています。埋めることが目的ではないので、案にない枠を足して1日を埋めることはしません(原則12)。

1. 明日の新しい枠(手順5の案で `booking_id` のない枠)は、`plan_timetable` の自律度に従います。`act_then_tell` なら手順5のとおりに入れます。`ask` なら、入れずに、明日の時間割を1件の `propose`(`kind: "plan_timetable"`)にします。`title` は「明日の時間割(枠 N件)」、`body` には枠を1行ずつ、時刻、題名、タスクか習慣の id の順で書きます。朝の秘書が了承を受けて、その行のとおりに `book` します。
2. 枠がない日は、入れることも案もありません。`left` に「見積りがない」タスクがあれば、見積りを本人に聞くこととして報告に書きます。
3. カレンダーへの書き出しは、手順5の6と同じく `write_calendar` の自律度に従います。

## 6b. 画面にだけある予定と、前のカレンダーの予定(カレンダーがあるときだけ)

共通の手引きの「画面にだけある予定と、前のカレンダーの予定」のとおりにします。

1. 手順1の `schedule` で、今日より先のタスクと習慣の予定のうち、組のないもの(`source` がないもの)を拾い、`write_calendar` の自律度に従って、メインのカレンダーに書くか、案にします。
2. 組の `source` が `google-calendar:<カレンダーの id>` のタスクや習慣の予定があれば、前のカレンダーからメインのカレンダーへ移す案を1件出します。何件を、どのカレンダーから移すかを書きます。自分では移しません。
3. 了承された移す案は、手順0で、共通の手引きの順(メインに作る、組を付け直す、前の予定を消す)で行い、移した件数を報告に書きます。

## 7. 閉じ忘れ(`close_forgotten`)

1. `stale` を読みます。日数は既定のままにします。
2. 候補ごとに `get` で記録を読み、終わった根拠を探します。今日の `activity` で、同じゴールの後ろのタスクが閉じた、手放したときの `next` が終わりを書いている、といった動きも根拠にします。根拠にするのはデータベースの記録と、`stale` の `merged` だけです。使う機械のファイルは見ません。
3. 根拠がはっきりしているものは、共通の手引きの「終わったタスクを閉じる」のとおりに、聞かずに閉じます。
4. 根拠が弱いものは、閉じず、案も出しません。週の完了確認で聞くので、ここでは報告に件数だけ書きます。先送りの日付はこちらで決めません。

## 8. ゴールにつながっていないタスク(`bundle_loose_tasks`、`move_task`)

ゴールのないタスクがたまっていたら、どのゴールに入れるか、新しいゴールにまとめるかの案を出します。入れる先がはっきりしているものは `propose`(`kind: "move_task"`)で、新しいゴールにまとめるものは `propose`(`kind: "bundle_loose_tasks"`)で出します。ゴールを作るのは本人が決めたときだけなので、新しいゴールは案にとどめます。`move_task` が `act_then_tell` で、入れる先のゴールがはっきりしているときだけ、`update` でゴールを付け替え、報告に書きます。

## 9. 人を集める

その日に分かった人のことを、そのプロフィールの「人」に足します。人のことは、自律度に関係なく、聞かずに書いてかまいません。

1. `activity` を引数なしで読み、閉じたタスクの成果(`result`)と、あれば記録の気づきから、人の名前と、その人について分かったこと(立場、担当、要望、やりとりの結果)を拾います。
2. 明日から1週間の予定のうち、本人のほかの参加者がいる予定から、まだ「人」にいない人を拾います(カレンダーがあるときだけ)。
3. プロフィールごとに `people` を読み、すでにいる人と、すでにあることは書きません。
4. いる人には `person` で、いない人は `person` で作ってから書きます。メールや所属、役職、`people` の `columns` にある列に当たるものはその列に、残りは `add_memos` のメモに書きます(起きたことは `kind: "やりとり"`)。推定は「〜らしい」と分かるように書きます。予定から読み取ったことは推測なので、列と `items` は `unverified: true` を付けて、メモは `mark: "未確認"` で書きます。確かな値がすでにある列は、推測で書き換えません。予定で会う人は、`person` の `link`(`kind: "booking"`)でその予定とつなぎます。
5. `people` の一覧の `unassigned`(だれのことか決まっていないメモ)を読み、名前から分かるものは、その人の `assign_memos` で付けます。決められないものは残します。メモのうち、列に当たるもの(誕生日、好きなもの、得意なことなど)は `promote_memos` で列に移します。
6. 足した人の数を、報告の「やってから知らせること」に1行で書きます。

## 8b. 近い誕生日

`people` を `birthdays_within: 14` で、プロフィールを渡さずに読みます。2週間以内に誕生日の人がいれば、報告の「決めてほしいこと」に「〇〇さんの誕生日が 11/20(あと6日)。プレゼントや連絡の用意をタスクにしますか」の形で1人1行書きます。好きなもの(`items`)が分かっていれば添えます。同じ人のことは、誕生日の前に一度だけ書きます(前の晩までの報告に書いていれば書きません)。タスクを作るのは、本人が「作って」と答えてからです。

## 10. 報告を書く

`report` を `kind: "nightly"` で書きます。題名は、決めてほしいことの数と、いちばん急ぐゴールを1行で書きます。本文は、決めてほしいこと(出した案の題名と、案にできないこと)、やってから知らせること(了承された案で行ったこと、組み直した枠の前後、入れた明日の時間割、閉じたタスク、取り込んだカレンダーの予定の数)、ゴールごとの見張りの結果(間に合う、危ない、見積もれない)の順にします。朝の報告がこれを読むので、ゴールの名前と、何が足りないかを具体的に書きます。
