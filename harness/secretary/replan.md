# 計画の組み直し(replan)

warifuri が「締切や見積もりが変わったので、計画を組み直します」と知らせてきました。締切つきのタスクが増えたか、タスクの締切や見積もりが変わりました。変わったタスクは、上の「変わったタスク」に並んでいます。本人に「計画を組み直して」と言われたときも、この手順で組み直します。本人はこの場にいないかもしれないので、聞かずに組み直して、変えたところを知らせます。

## 1. 読む

1. `settings` を読み、生活の決まり(`life.rules`)、場所と移動時間(`places`)、上限を確かめます。
2. `schedule` を、今から7日先まで読みます。

## 2. 案を作る

1. `timetable` を、`from` に今の時刻、`to` に7日後、`replan: true` を渡して読みます。warifuri が入れた作業の枠(組のない固定の予定ではないもの)のうち、これからのものは動かしてよい枠として扱われます。古く入った枠ほど残り、新しく入った枠から動きます。締切に間に合わないタスクが出るときは、新しい枠から順に外して入れ直します。
2. 案を、生活の決まりに照らして確かめます(締切の2日前に終わる位置、日曜に義務を置かない、など。日曜の予備の枠は外しません)。決まりに合わない枠だけを外すか、`free_time` の空きの中で置き直します。上限は超えません。
3. 平日に入りきらない分は、案のとおり土曜に置きます(土曜の上限は平日と同じです)。日曜は義務を置かない日なので、案は日曜に枠を置きません。ただし、締切に間に合わないタスクが出るときだけ、日曜に予備の枠(`spare: true`)を1つ置きます(締切がその日曜から4日のうちにあるとき)。本人に知らせるときは、日曜の予備の枠であることを添えます。

## 3. 入れる

動かしてよいのは、warifuri が作った予定(タスクの枠と移動の予定)だけです。本人が入れた予定(組のない固定の予定と、本人がカレンダーで動かした枠)は、動かしも消しもしません。

1. `blocks` のうち `booking_id` のある枠は、その id を付けた `book` で時刻を動かします。`booking_id` のない枠は、新しく `book` で入れます(タスクの枠は `kind: "task"` と `task_id`、習慣の枠は `kind: "habit"` と `habit_id`)。
2. `travel` の移動は、`book` に `kind: "travel"`、題名「移動」、始まりと終わりを渡して入れます。`booking_id` があれば、その id で動かします。場所(`location`)は付けません。`short: true` の移動は、前の予定との間に移動の時間が足りません。そのことを知らせに1行で書きます。
3. `unbook` に並んだ予定を `unbook` で消します。warifuri が作った予定だけが並びます。
4. 人が主導するゴールの枠(`human_led` が true)は、入れずに案として知らせます(原則8)。
5. カレンダーがあり、`write_calendar` が `act_then_tell` のときは、動かした予定に組のあるカレンダーの予定も同じ時刻に直し、新しい予定と移動の予定を本人のメインのカレンダーに書いて組にします(説明の最後の行に「warifuri で作成」)。消した予定に組のあるカレンダーの予定も消します。`ask` のときは、書き出すかを `ask`(`kind: "write_calendar"`)で聞きます。

## 4. 知らせる

1. 返事の1行目は「直近の状況を見て、こう組み直しました。どうですか」にします。
2. 続けて、`changes` の `line` を1件1行の箇条書きで並べます(どの枠を、いつからいつへ動かしたか、新しく入れた枠、外した枠)。変えたところがなければ「組み直しましたが、変えた枠はありません」の1行だけにします。
3. `left` に `misses_due: true` のタスクがあれば、締切までに入らないことと、あと何分足りないかを書き、`reply_options` で選べる形にします(ほかの予定を動かす、締切を本人が変える、分けて入れる)。締切は秘書が変えません。
4. `show_calendar` で、変えた日の前の日から1週間ほどを返事の下に出します。`marks` には、動かした予定と入れた予定の id を渡します。
5. この返事は、画面と Discord に届きます。本人が「戻して」と言ったら、`changes` の `before` の時刻に戻します。
