# warifuri の構成

この文書には、[思想](思想.md)から導いた warifuri の組み立てを書きます。2つの文書が食い違ったときは、思想のほうを正とします。

## 全体の形

warifuri の核は、ゴールとタスクの台帳と、それを MCP で開く口の2つです。スケジュール、カレンダー、秘書、話す窓口などは、要るものだけを差し込みとして足します。

Claude Code を使う機械が何台あっても、どれも同じ台帳を同じ口で読み書きします。

```
  Mac の Claude Code ─────┐
  Windows の Claude Code ─┼─ MCP ─▶ ┌──────── warifuri のサーバー ────────┐
  ほかの PC ───────────────┘         │ 核: 台帳、MCP の口、小さな HTTP API │
                                    │ ─────────────────────────────────── │
                                    │ 差し込み(入れたいものだけ)          │
                                    │   スケジュール、カレンダー、秘書、    │
                                    │   話す窓口、機械                      │
                                    └─────────────────────────────────────┘
```

## 核1: 台帳

### サーバーが持つもの

台帳は SQLite のファイル1つです。持つものは次のとおりです。

| もの | 主な項目 | 原則 |
|---|---|---|
| ゴール | 題名、あるべき姿、期日、状態、だれの時間を使うか、人が主導か、分野、秘密度 | 1, 2, 8, 20 |
| タスク | 題名、完了の条件、ゴール、状態、だれの時間を使うか(`mode`)、見積り、期限(任意)、置き場 | 3, 4, 5, 6 |
| 順序 | タスクどうしの「こちらが先」 | 3 |
| 習慣 | 題名、繰り返しの決まり(毎週金 9:00〜10:30 など)、長さ、つながるゴール | 21 |
| 置き場 | 名前、秘密度、探すための分野と、機械ごとのディレクトリ(同じ置き場でも Mac と Windows で道が違う) | 20 |
| 秘書の段 | 秘書の動きの種類ごとの段と、了承・取り消しの回数。秘書を入れ替えても残るように台帳に置く | 13 |
| 記録 | だれが、いつ、何を変えたか | 9, 18 |

習慣は、ゴールやタスクとは別の表です。終わりのないものをゴールとタスクに混ぜないためです(原則21)。知識は台帳に入れません。

ゴールとタスクの状態は、`ready`、`running`、`needs_human_input`、`deferred`、`done`、`discarded` の6つです。

### 決まりは台帳が守る

決まりは、AI が覚えていることに頼らず、台帳が書き込みを受けつけるかどうかで守ります(原則11)。決まりに合わない書き込みは、何も書かずに断り、足りないものを返します。

人の時間を使うゴールは、あるべき姿と、人が決めた期日がないと作れません。仮の期日では足りません(原則1、2)。人の時間を使うタスクは、完了の条件がないと作れません(原則5)。待ちにするにはだれの何を待つか、完了には成果、破棄には理由、先送りにはいつ見直すかが要ります(原則5、6)。

変更はすべて、どの鍵で、だれとして書かれたかを記録に残します。ただし鍵は機械ごとなので、同じ機械の人と AI を台帳は見分けられません。期日を人が決めたかどうかは、いまは書き手の申告によります。

秘密度が「出さない」のものは、MCP の応答で題名、状態、期日だけを返します。中身は、その秘密度を読んでよい機械にだけ返します。タスクの秘密度は、タスク、ゴール、置き場のうち厳しいものを取ります。

## 核2: MCP の口

### 道具

最初の版で出す道具です。

| 道具 | やること | 主に使う人 |
|---|---|---|
| `board` | 開いているゴールと、その下のタスクを一覧する。分野、状態、`mode` で絞れる | みんな |
| `get` | ゴールかタスクを1件、順序と記録つきで読む | みんな |
| `search` | 題名で探す。作る前に、同じものがないかを見る | エージェント |
| `create_goal` | ゴールを作る | エージェント、秘書 |
| `create_task` | タスクを作る。ゴールなしでも作れる | エージェント、秘書 |
| `update` | 題名、完了の条件、期限、`mode`、ゴールの付け替えを直す | みんな |
| `link` / `unlink` | タスクどうしの順序を足す、外す | みんな |
| `start` | いまこのタスクをやっていることを、機械と置き場ごとに残す | エージェント |
| `close` | 完了か破棄にする。成果か理由を付ける | エージェント、秘書 |
| `defer` | 先送りにする。いつ見直すかを付ける | エージェント、秘書 |
| `wait` | 待ちにして、だれの何を待つかを書く | エージェント |

差し込みも、自分の道具をこの口に足せます。たとえばスケジュールの差し込みは、人の空き時間を聞く `free_time` と、ブロックを入れる `book` と `unbook` を足します。

### HTTP API

作業の前に今のタスクがあるかを確かめるフックのように、AI ではなくスクリプトが台帳に聞く場面があります。そのために、同じ操作を素の HTTP でも出します。フックは Node で書き、Mac、Windows、Linux で同じものを使います。

### つなぎ方

機械ごとに鍵を1つ発行し、その機械で1回だけ次のように登録します。

```bash
claude mcp add --transport http warifuri https://<サーバー>/mcp --header "Authorization: Bearer <その機械の鍵>"
```

鍵を機械ごとに分けるのは、どの機械が変えたかを記録に残し、失くした機械の鍵だけを止められるようにするためです。claude.ai やスマホのアプリから使うには OAuth が要るので、最初の版では鍵だけにして、あとで足します。

### 届かないとき

台帳に届かないときも、作業は止めません。フックは、台帳に届かなければ通します。届かなかった `start` と `close` はその機械の手元に残し、次に届いたときにフックがまとめて送ります。エージェントが覚えていることには頼りません。読むほうは、最後に取った一覧の写しで済ませます。

## 置き方と届け方

サーバーは Node だけで動くので、Mac、Windows、Linux のどれにも置けます。最初は、ふだん使っている機械1台で始めれば十分です。

| 置き方 | 口 | 要るもの | 向いている人 |
|---|---|---|---|
| 同じ機械 | `localhost` | なし | まず試す人、1台で使う人 |
| Tailscale の中 | tailnet の中の名前 | Tailscale のアカウント(無料) | 自分の機械どうしで使う人 |
| Tailscale Funnel | `*.ts.net` の HTTPS | Tailscale のアカウント(無料) | VPN を入れられない機械からも使う人 |
| 自宅のサーバー | Cloudflare Tunnel と Access | Cloudflare のアカウントと独自ドメイン | 守りを二重にしたい人 |
| VPS | Caddy などで HTTPS を受ける | VPS と名前(独自ドメインか、無料の DNS) | 家に常時動く機械がない人 |

おすすめは表の上からで、独自ドメインと Cloudflare はなくてもかまいません。どの置き方でも、warifuri は機械ごとの鍵で相手を確かめます。Funnel や VPS のように外に出す置き方では、この鍵が守りのすべてになります。

台帳が受ける口は、MCP と、同じ中身の HTTP API で、どちらも同じ鍵で確かめます。Web 画面のように自分の口を持つ差し込みは、何の口をどこに開けるかを、その差し込みの説明に書きます。台帳を使うことを VPN に頼る作りにはしませんが、VPN の中だけで使うかどうかは使う人が選べます。

## 差し込み

### 用意する差し込み

差し込みを1つも入れなくても、核は台帳として動きます。

| 差し込み | やること | 要るもの |
|---|---|---|
| スケジュール | 人の空き時間を探してブロックを置く。習慣を先に置き、上限を守る | 個人の事実(生活、場所と移動、上限) |
| カレンダー | 固定の予定を読み、スケジュールを専用のカレンダーに書く | Google の接続 |
| 秘書 | ゴールが期日に間に合うかを毎晩見て、段に従って組み直しや閉じ忘れの処理をする | サーバーで動く Claude Code(使う人のサブスクリプション) |
| 窓口: Discord | 秘書と話し、報告を受け取る | Discord のボット |
| 窓口: Web 画面 | スケジュールと台帳を見て、秘書と話す | ログインの口 |
| 機械: 監視 | サーバーの様子を答える | Prometheus など |
| 機械: 作業用ブラウザ | 調べものを代わりに見に行く | ブラウザを動かす VM か PC |
| 機械: 実装用の手 | コードの直しを、隔離した機械で書いてテストする | 専用の VM |

秘書として使うなら、核にスケジュール、カレンダー、秘書、Discord を足した組み合わせが基本になります。秘書を入れず、エージェントが `free_time` と `book` を呼ぶだけの使い方もできます。

作業用ブラウザと実装用の手は、立てる手間も危うさも大きいので、warifuri には入れません。個人の差し込みとして書く例を示すだけにします。ほかは warifuri の差し込みとして用意します。

### 差し込みの形

warifuri が用意する差し込みも、使う人が自分で書く差し込みも、同じ形にします。差し込みが出せるものは次の4つです。

| 出せるもの | 例 |
|---|---|
| MCP の道具 | 監視の `server_status`、作業用ブラウザの `browse` |
| 定時の仕事 | 毎晩の組み直し、10分おきの見張り |
| 秘書への説明 | その差し込みの道具をいつどう使うか。秘書の指示書に足される短い文 |
| 設定の形 | その差し込みが読む設定の項目と、既定値 |

差し込みが台帳に触れるのは核の API からだけで、期日や完了の条件、秘密度の決まりは差し込みからも外せません。ほかの差し込みを使うときも、MCP の口に出ている道具を通します。直接は呼びません。

差し込みはどこに置いてもかまいません。warifuri の `plugins/` の中、手元のフォルダ、npm のパッケージのどれでも、`差し込み.yaml` に書けば読み込みます。差し込みは使う人が信じて入れるコードなので、足す道具、外への通信、定時の仕事を説明の欄に書かせ、入れるときに使う人へ見せます。

### バニラと個人の拡張

```
warifuri(公開。手を入れずにそのまま使える)
   ▲ 依存する(写して改造はしない)
個人の設定リポジトリ(非公開)
   ├─ 設定: 思想の書き換え、生活、場所、分野、習慣、上限
   └─ 個人の差し込み: 自分の環境に合わせた機械など
```

warifuri は、設定を書くだけで動くようにします。自分の環境に合わせたいことは、warifuri を写して改造せず、設定と個人の差し込みで行います。こうしておけば、warifuri を新しい版にしても個人の部分はそのまま残ります。

個人の差し込みのうちほかの人にも使えそうなものは、固有の語を設定へ出してから warifuri に戻します。核を変えないとできないことは、個人の側で抱えず、warifuri への変更として出します。

## 使う人が書く設定

| ファイル | 中身 |
|---|---|
| `思想.md` | 合わない原則の書き換え |
| `生活.md` | 生活の前提と、予定の固さ |
| `場所.md` | 場所と移動時間の表 |
| `分野.yaml` | 分野の一覧と、分野ごとの既定(人が主導か、秘密度、スケジュールの色) |
| `習慣.yaml` | 最初に入れる繰り返しの予定。あとは秘書との会話で足す |
| `上限.yaml` | 1日の上限、ブロックの区切り、置ける時刻 |
| `差し込み.yaml` | 入れる差し込み |
| `.env` | 鍵とトークン。git に入れない |

名前、ドメイン、分野の名前、ディレクトリの道は、すべて設定から読み、コードには書きません。秘書を入れた場合は、最初の会話で秘書が `生活.md`、`場所.md`、`分野.yaml`、`習慣.yaml` を一緒に作ります。設定のひな形は、架空の人の例として `examples/` に置き、写して書き換えれば動く形にします。
