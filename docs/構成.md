# warifuri の構成

第1版(2026-10)。`思想.md` から導いた構成。思想と食い違ったら、思想のほうを正とする。

## ひとことで

> **核は、ゴールとタスクの台帳と、それを MCP で開く口。**
> スケジュール、カレンダー、話す窓口、機械は、必要に応じて差し込む。

Claude Code を使うすべての機械(Mac、Windows、ほかの PC)から、同じ台帳を同じ口で見て、書く。

```
  Mac の Claude Code ──┐
  Windows の Claude Code ─┼─ HTTPS(MCP)──▶ [ 認証の口 ] ──▶ ┌──────────── warifuri サーバー ─────────────┐
  ほかの PC ────────────┘                                      │ 核: 台帳 + MCP の口 + 小さな HTTP API     │
  (将来)claude.ai / スマホ ─ 同上(OAuth)                     │ ─────────────────────────────────────── │
                                                               │ 差し込み(入れたいものだけ)              │
                                                               │   スケジュール … 空きを探す、ブロックを置く │
                                                               │   カレンダー … Google カレンダーを読む・書く │
                                                               │   秘書     … 毎晩の見張りと組み直し(AI)   │
                                                               │   窓口     … Discord、Web 画面           │
                                                               │   機械     … 作業用ブラウザ、実装用の手、監視 │
                                                               └──────────────────────────────────────────┘
```

---

## 1. 核: 台帳

### 持つもの

| もの | 主な項目 | 思想の原則 |
|---|---|---|
| ゴール | 題名、あるべき姿(完了の目安)、期日、状態、人が主導か、分野、秘密度 | 1, 2, 8, 20 |
| タスク | 題名、完了の条件、ゴール、状態、だれの時間を使うか(`mode`)、見積り、期限(任意)、置き場 | 3, 4, 5, 6 |
| 順序 | タスクどうしの「これが先」(`blocks`) | 3 |
| 習慣 | 題名、繰り返しの決まり(毎週金 9:00〜10:30 など)、長さ、つながるゴール | 21 |
| 置き場 | ディレクトリと、その分野・秘密度。機械ごとの道(同じプロジェクトでも Mac と Windows で道が違う) | 20 |
| 自律の段 | 秘書の動きの種類ごとの段(聞いてから / やってから知らせる)と、了承・取り消しの回数 | 13 |
| 記録 | だれが、いつ、何を変えたか(人、秘書、どの機械のどのエージェント) | 9, 18 |

- 状態は、`ready`、`running`、`needs_human_input`(だれの何を待つかが必須)、`deferred`、`done`(成果が必須)、`discarded`(理由が必須)の6つにする。
- 知識は台帳に入れない(原則 21)。

### 守りを台帳の側で持つ

決まりは、AI が覚えていることに頼らず、台帳が受けつけるかどうかで守る(原則 11)。

- 人の時間を使うゴールは、期日がないと作れない(原則 2)。
- 人の時間を使うタスクは、完了の条件がないと作れない(原則 5)。
- `done` には成果、`discarded` には理由が要る。
- 秘密度が「出さない」のものは、MCP の応答で題名・状態・期限だけを返す。中身は、その秘密度を読める機械からだけ返す。

## 2. 核: MCP の口

### 道具(最初の版)

| 道具 | やること | だれが使う |
|---|---|---|
| `board` | 開いているゴールと、その下のタスクを一覧する(分野・状態・mode で絞れる) | みんな |
| `get` | ゴールかタスクを1件、順序と記録つきで読む | みんな |
| `search` | 題名で探す(作る前に、同じものがないか見る) | エージェント |
| `create_goal` | ゴールを作る(期日の決まりは台帳が見る) | エージェント、秘書 |
| `create_task` | タスクを作る(ゴールなしも仮置きとして可) | エージェント、秘書 |
| `update` | 題名・完了の条件・期限・mode・ゴールの付け替え・順序 | みんな |
| `start` | 「いまこのタスクをやっている」を、機械と置き場ごとに記録する | エージェント |
| `close` | `done`(成果)、`discarded`(理由)、`deferred`(いつまで) | エージェント、秘書 |
| `wait_for_human` | `needs_human_input` にして、だれの何を待つかを書く | エージェント |
| `free_time` | 人の時間の空きを聞く(スケジュールの差し込みがあるとき) | エージェント |
| `book` / `unbook` | 人のスケジュールにブロックを入れる・外す(同上) | エージェント、秘書 |

### HTTP API(同じ中身の、もう1つの口)

フック(作業の前に、いまのタスクがあるかを確かめるもの)のように、AI ではなくスクリプトが台帳に聞く場面のために、同じ操作を素の HTTP でも出す。フックは Node で書き、Mac・Windows・Linux で同じものを使う。

### つなぎ方(各機械で1回)

```bash
claude mcp add --transport http warifuri https://<サーバー>/mcp --header "Authorization: Bearer <その機械の鍵>"
```

- 鍵は機械ごとに1つ発行する。記録に「どの機械が変えたか」が残る。失くした機械の鍵だけを止められる。
- claude.ai やスマホのアプリから使うには OAuth が要る。最初の版は鍵だけにし、あとで足す。

サーバーは `warifuri serve --db <台帳>` で立てる。既定では 127.0.0.1 だけで受け、外から受けるかは使う人が決める(そのときの守りは鍵だけになる)。鍵は `warifuri key add <機械の名前> --db <台帳>` で発行し、表示は1回きりにする。台帳には鍵のハッシュだけを置く。「出さない」ものまで読ませる機械には `--read-withheld` を付ける。止めるのは `warifuri key revoke` で行う。

### つながらないとき(原則: 作業を止めない)

- フックは、台帳に届かなければ通す。
- 届かなかった `start` と `close` は、その機械の手元に記録しておき、次に届いたときにまとめて送る。送るのはフックの仕事にする(エージェントの記憶に頼らない)。
- 読むのは、最後に取った一覧の写しで済ませる。

## 3. 届け方(どのネットワークからでも)

| 置き方 | 口 | 向いている人 |
|---|---|---|
| 自宅のサーバー | Cloudflare Tunnel。前に Access(サービストークンか OAuth) | 家に常時動く機械がある人 |
| VPS | Caddy などで HTTPS を直接受ける。鍵を必須にする | 家に常時動く機械がない人 |
| 使っていない PC | Cloudflare Tunnel か Tailscale Funnel | 家の古い PC を使う人 |

- サーバーが外から受けつけるのは、この1つの口だけにする。
- VPN(Tailscale など)は管理の近道として残すが、台帳を使うことは VPN に頼らない。

## 4. 差し込み

差し込みは、核の台帳を読み書きするだけで、ほかの差し込みには直接触らない。入れなくても核は動く。

| 差し込み | やること | 要るもの |
|---|---|---|
| スケジュール | 人の時間の空きを探し、ブロックを置く。習慣を先に置く。上限を守る | 個人の事実(生活、場所と移動、上限) |
| カレンダー | 固定の予定を読み、スケジュールを専用のカレンダーに書く | Google の接続 |
| 秘書 | 毎晩、ゴールが間に合うかを見て組み直す。閉じ忘れを拾う。自律の段を守る | サーバーで動く Claude Code(使う人のサブスクリプション) |
| 窓口: Discord | 秘書と話す。報告を受け取る | Discord のボット |
| 窓口: Web 画面 | スケジュールと台帳を見る。秘書と話す | ログインの口 |
| 機械: 作業用ブラウザ | 調べものを代わりに見に行く | ブラウザを動かす VM か PC |
| 機械: 実装用の手 | コードの直しを、隔離した機械で書いてテストする | 専用の VM |
| 機械: 監視 | サーバーの様子を答える | Prometheus など |

- 最小の形は「核 + スケジュール + カレンダー + 秘書 + Discord」。機械の差し込みは、要る人だけ。
- 公式の差し込みにするのは、上の表のうち、機械の差し込み以外と、監視(Prometheus を読む形)。作業用ブラウザと実装用の手は、立てる手間と危うさが大きいので、公式には入れず、個人の差し込みとして書く例にとどめる。
- 秘書を入れずに、核とスケジュールだけで使うこともできる(エージェントが `free_time` と `book` を呼ぶだけ)。

### 差し込みの形

公式の差し込みも、使う人が自分で書く差し込みも、同じ形にする。

| 差し込みが出せるもの | 例 |
|---|---|
| MCP の道具 | 監視の `server_status`、作業用ブラウザの `browse` |
| 定時の仕事 | 毎晩の組み直し、10分おきの見張り |
| 秘書への説明 | その差し込みの道具を、いつ・どう使うか(秘書の指示書に足される短い文) |
| 設定の形 | その差し込みが読む設定の項目と、既定値 |

- 差し込みが台帳に触れるのは、核の API を通してだけ。台帳の決まり(期日、完了の条件、秘密度)は、差し込みからも外せない。
- 差し込みは、ほかの差し込みに直接触らない。
- 差し込みは、どこに置いてもよい。warifuri の `plugins/` の中、使う人の手元のフォルダ、npm のパッケージのどれでも、`差し込み.yaml` に書けば読まれる。
- 差し込みは、使う人が信じて入れるコードとして扱う。何をするか(足す道具、外への通信、定時の仕事)は、差し込みの説明の欄に書かせ、入れるときに使う人へ見せる。

### バニラと、個人の拡張

```
warifuri(公開。手を入れずにそのまま使える)
   ▲ 依存する(写して改造はしない)
個人の設定リポジトリ(非公開)
   ├─ 設定: 思想の書き換え、生活、場所、分野、習慣、上限
   └─ 個人の差し込み: 自分の環境に合わせた機械など
```

- warifuri は、設定を書くだけで動く(バニラ)。公式の差し込みも、設定で入れ切りできる。
- 個人の環境に合わせたいことは、warifuri を写して改造するのではなく、設定と個人の差し込みで行う。warifuri を新しい版にしても、個人の部分はそのまま残る。
- 個人の差し込みのうち、ほかの人にも使えそうなものは、固有の語を設定へ出してから、warifuri へ戻す(公式の差し込みにするか、別のパッケージとして出す)。
- 核を変えないと実現できないことは、個人の側で抱えず、warifuri への変更として出す。

## 5. 設定(使う人が書くもの)

| ファイル | 中身 |
|---|---|
| `思想.md` | 合わない原則を書き換える |
| `生活.md` | 生活の前提、予定の固さ |
| `場所.md` | 場所と移動時間の表 |
| `分野.yaml` | 分野の一覧と、分野ごとの既定(人が主導か、秘密度、スケジュールの色) |
| `習慣.yaml` | 繰り返しの予定(初めに入れるもの。あとは秘書との会話で足す) |
| `上限.yaml` | 1日の上限、ブロックの区切り、置ける時刻 |
| `差し込み.yaml` | どの差し込みを入れるか |
| `.env` | 鍵とトークン(git に入れない) |

- 名前、ドメイン、仕事の分野名、ディレクトリの道は、すべて設定から読む。コードに書かない。
- 最初の会話で、秘書が `生活.md`、`場所.md`、`分野.yaml`、`習慣.yaml` を一緒に作る。
- 設定のひな形を `examples/` に置く。架空の人の例で、そのまま写して書き換えれば動く形にする。
