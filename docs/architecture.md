# warifuri の構成

この文書には、[原則](principles.md)から導いた warifuri の組み立てを書きます。2つの文書が食い違ったときは、原則のほうを正とし、この文書を直します。

## 言葉

| 言葉 | 意味 |
|---|---|
| 人、本人 | warifuri のサーバーを使う1人 |
| サーバーの機械 | warifuri のサーバーを動かしている機械 |
| 使う機械 | ハーネスで warifuri につないでいる機械。台帳では「デバイス」と呼び、機械ごとに1つの名前を持つ |
| 台帳 | ゴール、タスク、順序、持つの記録、習慣、置き場、秘書の段、変更の記録を入れた SQLite のファイル |
| 核 | 台帳、MCP の口、HTTP API、プロフィールと設定の配布 |

## 全体の形

warifuri の核に、スケジュール、カレンダー、秘書、話す窓口などを、要るものだけ差し込みとして足します。

使う機械が何台あっても、どのハーネスからでも、同じ台帳を同じ口で読み書きします。

```
  Mac の Claude Code ──────┐
  Mac の Codex ────────────┤
  ほかの PC のハーネス ─────┼─ MCP(GitHub でログイン) ─▶ ┌────── warifuri のサーバー ──────┐
                           │                             │ 核: 台帳、MCP の口、HTTP API、  │
  使う機械のフック ─────────┴─ HTTP(機械の鍵) ────────▶ │     プロフィールと設定           │
                                                         │ ─────────────────────────────── │
                                                         │ 差し込み(入れたいものだけ)      │
                                                         │   スケジュール、カレンダー、     │
                                                         │   秘書、話す窓口、機械           │
                                                         └─────────────────────────────────┘
```

## 核1: 台帳

### 台帳が持つもの

| もの | 主な項目 | 原則 |
|---|---|---|
| ゴール | 題名、あるべき姿、期日(仮の印つきもある)、状態、だれの時間を使うか、人が主導か、プロフィール | 1, 2, 8, 20 |
| タスク | 題名、説明(`body`)、完了の条件、ゴール、状態、だれの時間を使うか(`mode`)、重さ(`load`)、見積り、期限(任意)、置き場、次の一手(`next`)、任せるの印 | 3, 4, 5, 6, 8 |
| 順序 | タスクどうしの「こちらが先」 | 3 |
| 持つ | どのタスクを、どのデバイスの、どの置き場で、いつから作業しているか | 7 |
| 習慣 | 題名、繰り返しの決まり(毎週金 9:00〜10:30 など)、長さ、つながるゴール | 21 |
| 置き場 | 名前、属するプロフィール、デバイスごとのディレクトリ(同じ置き場でも Mac と Windows で道が違う) | 20 |
| 秘書の段 | 秘書の動きの種類ごとの段と、了承・取り消しの回数 | 13 |
| 記録 | だれが、どのデバイスから、いつ、何を変えたか。プロフィールと設定の変更も入る | 9, 18 |

ゴールとタスクの状態は、`ready`、`running`、`waiting`、`deferred`、`done`、`discarded` の6つです。`waiting` は待ちで、本人の判断を待つときも、指導教員や先方の返事のように人の外を待つときも使います。

重さ(`load`)は「重い・普通・軽い」の3つで、任意です。人の時間を使うタスクで分かるときだけ入れ、空なら普通として扱います。スケジュールを組むとき、重い作業を集中できる時間に置くために使います。説明(`body`)は背景と範囲を書く欄で、目安は2,000字までです。長い仕様や手順はリポジトリの文書に置き、その場所を書きます。

優先度の数字は持ちません。どれを先にやるかは、ゴールの期日、順序、秘書の判断から出します。秘書がいなければ、人とエージェントがこれらから決めます。

習慣はゴールやタスクとは別の表です(原則21)。知識は台帳に入れず、プロフィールに置きます(原則21、22)。

### 持つ

エージェントは、作業を始めるときに `start` でタスクを持ちます。

- 1つのタスクを持てるのは1か所です。別のデバイスや置き場で `start` すると持ち主が移り、そのことが記録に残ります。
- 同じデバイスの同じ置き場で持てるのは1件です。すでに1件持っているところで別のタスクを `start` すると断り、いま持っている1件を返します。先に手放してから始めます。置き場で持っているこの1件が、その置き場の「いまの1件」で、着手の確かめ(下の HTTP API)はこれを見ます。
- 同じ機械で Claude Code と Codex を使っても、デバイスは1つです。どちらから `start` しても同じ「いまの1件」を見ます。
- 閉じる、待ちにする、先送りにする、中断する(`release`)のどれかで手放します。手放すときは、次に持つ人のために `next` を1行書きます。
- `board` と流れ図には「mac で作業中」のように出ます。

### 決まりは台帳が守る

決まりは、AI が覚えていることに頼らず、台帳が書き込みを受けつけるかどうかで守ります(原則11)。決まりに合わない書き込みは、何も書かずに断り、足りないものを返します。

人の時間を使うゴールは、あるべき姿と期日がないと作れません。仮の印の付いた日付は期日として受けつけません(原則1、2)。人の時間を使うタスクを持つゴールは、人の時間を使うゴールとして扱います。人の時間を使うタスクは、完了の条件がないと作れません(原則5)。待ちにするにはだれの何を待つか、完了には成果、破棄には理由、先送りにはいつ見直すかが要ります(原則5、6)。

変更はすべて、だれとして、どのデバイスから書かれたかを記録に残します。ただし、同じデバイスの人と AI は、台帳からは見分けられません。期日を人が決めたかどうかは書き手の申告によります(原則2)。

warifuri は、台帳の中で見せる範囲を区切りません。ログインした本人には全部が見えます。

### 外から取り込む

ほかの道具からの引っ越しや写しのために、台帳はスナップショットの JSON を受け取れます([スナップショット](snapshot.md))。取り込みは、「決まりに合わない書き込みは断る」という決まりの唯一の例外です。決まりに合わない行も、要確認の印(`review`)を付けて入れます。印の付いた行は、次に書き換えるときに決まりを満たさなければ書けません。満たせば印は消えます。

## 核2: MCP の口

### 道具

| 道具 | やること | 主に使う人 |
|---|---|---|
| `board` | 開いているゴールと、その下のタスクを一覧する。置き場を渡すと、既定でその置き場のプロフィールの分だけ返す。全部を見たいときは明示する | みんな |
| `get` | ゴールかタスクを1件、順序と記録と説明つきで読む | みんな |
| `places` | 置き場を、プロフィールとデバイスごとの道つきで一覧する。タスクがまだない置き場も出る | エージェント、秘書 |
| `search` | 題名で探す。作る前に、同じものがないかを見る。閉じたものも探せる | エージェント |
| `flow` | ゴールごとの流れ図を Mermaid で返す。順序の矢印と、状態(済み、作業中、次にやれる、待ち)の色 | みんな |
| `stale` | 片づけの候補を出す。持ったまま動きがない、`ready` のまま長く触られていない、待ちのまま動きがない、など。日数はプロフィールの既定値で変えられる。閉じはしない | 秘書、人 |
| `create_goal` / `create_task` | ゴールやタスクを作る。タスクはゴールなしでも作れる | エージェント、秘書 |
| `update` | 題名、説明、完了の条件、期限、`mode`、重さ、ゴールの付け替え、人が主導の印と任せるの印を直す | みんな |
| `link` / `unlink` | タスクどうしの順序を足す、外す | みんな |
| `start` / `release` | タスクを持つ、手放す(手放すときは `next` を書く) | エージェント |
| `close` | 完了か破棄にする。成果か理由を付ける。分かったことがあれば一緒に渡す | エージェント、秘書 |
| `reopen` | 完了や破棄から `ready` に戻す | 人、秘書 |
| `resume` | 先送りや待ちから `ready` に戻す | エージェント、秘書 |
| `defer` | 先送りにする。いつ見直すかを付ける | エージェント、秘書 |
| `wait` | 待ちにして、だれの何を待つかを書く | エージェント |
| `habit` | 習慣を作る、直す、止める | 秘書、人 |
| `place` | 置き場を登録する、直す(プロフィール、デバイスごとの道) | エージェント、秘書 |
| `context` | 置き場を渡すと、そのプロフィールの people.md と knowledge.md、`knowledge/` と `procedures/` の中のファイル名の一覧を返す。手順や分けた知識の本文は、名前で取りにいく | エージェント |
| `note` | 知識に書く。人の言葉は「本人の言葉」としてすぐに知識へ、エージェントの気づきは受け箱へ(秘書がいなければ「未確認」として知識へ) | エージェント、秘書 |
| `profile` / `settings` | プロフィールの既定値と、使う人の設定(生活、場所、上限など)を読む、書く | 秘書、人 |
| `autonomy` | 秘書の段の一覧を読む。人の明示で段を変える | 人、秘書 |

書く道具は、呼び出したデバイスとして書きます。デバイスは機械の鍵か GitHub のログインのトークンから決まり、道具の引数では渡せません。記録の「だれとして」には鍵の種類が入ります。機械の鍵なら `device-key`、GitHub のログインならアプリの `oauth:<client_id>` です。決まりに合わず断った書き込みは、道具のエラーとして、足りないものを日本語で並べて返します。

`start` の置き場は、置き場の id か、作業しているディレクトリで渡します。ディレクトリなら、そのデバイスでそこを含む一番深い置き場を使います。どの置き場にも入らないディレクトリでは断り、`place` で登録するよう返します。`release` では `next` を1行書くことが要ります。

`close` で渡した「分かったこと」は、`note` ができたら同じ道で入れます。それまでは、閉じたときの記録に残すだけです。

差し込みも、自分の道具をこの口に足せます。たとえばスケジュールの差し込みは、人の空き時間を聞く `free_time` と、ブロックを入れる `book` と `unbook` を足します。

### HTTP API

作業の前に、この置き場に持っているタスクがあるかを確かめるフックのように、AI ではなくスクリプトが台帳に聞く場面があります。こうした場面のために、素の HTTP の口を出します。スクリプトは、人のログインではなく、機械の鍵(`warifuri key add <デバイスの名前>`)で台帳に聞きます。鍵はデバイスに結びつくので、フックは自分のデバイスの「いまの1件」を見ます。

いまの HTTP API は、着手の確かめに使う `GET /api/held?dir=<絶対パス>` の1つです。`Authorization: Bearer wf_…` に機械の鍵を付けて聞くと、そのディレクトリが入る置き場と、そこでこのデバイスが持っているタスクを返します。どちらもなければ null です。どの置き場にも入らないディレクトリでは、置き場の外で持っているタスクを返します。GitHub のログインのトークンは、MCP の口のために出したものなので、ここでは受けつけません。呼び出しの回数は、呼び出し元のアドレスごとに1分に600回までです。

### つなぎ方

使う機械は、ハーネスに URL を登録すれば使えます。初回にブラウザが開くので、GitHub でログインし、許可の画面でこの機械のデバイスの名前を選びます(新しく付けるか、同じ機械の別のハーネスで付けた名前を選ぶ)。

```bash
claude mcp add --transport http warifuri https://<サーバー>/mcp
```

ハーネスごとの登録の仕方の違いは、`warifuri connect` が吸収します。使っているハーネスを見つけて、登録と、任意のもの(着手の確かめのフックと機械の鍵、エージェントへの指示書のひな形)を入れます。`connect` とフックを使うときだけ、使う機械にも warifuri を入れます。

ログインしてよい人は、設定に GitHub のユーザー名で1人だけ書きます。そこにない人は、ログインできても断ります。ただし、GitHub のユーザー名は手放されると別の人が取れるので、本人かどうかは名前ではなく GitHub の数値の ID で比べます。`WARIFURI_GITHUB_ID` に ID を書けばそれを使い、書かなければ、名前が合った最初のログインの ID を台帳に覚えて、それからは ID だけを比べます。覚えた ID は `warifuri oauth clients` の最初の行に出ます。warifuri は、自分で OAuth の口になり、本人の確認だけを GitHub に任せます。GitHub のトークンをそのまま台帳の鍵として使うことはしません。

GitHub でのログインには、GitHub の OAuth App を1つ作ります。GitHub の Settings の Developer settings にある OAuth Apps で新しく登録し、Authorization callback URL に `<公開の URL>/oauth/github/callback` を書きます。公開の URL は、ハーネスから見えるサーバーの URL です。`https://` で始まり、道を含まない形にします(手元で試すときだけ `http://localhost` も使えます)。サーバーには、公開の URL を `WARIFURI_PUBLIC_URL` で、ログインしてよい人の GitHub のユーザー名を `WARIFURI_GITHUB_USER` で、OAuth App の Client ID と Client Secret を `WARIFURI_GITHUB_CLIENT_ID` と `WARIFURI_GITHUB_CLIENT_SECRET` で渡します。Secret は秘密なので `secrets.env` に書くか、`WARIFURI_GITHUB_CLIENT_SECRET_FILE` でファイルの場所を渡します。前の2つは `warifuri serve` の `--public-url` と `--github-user` でも渡せて、そのときは引数のほうを使います。書く場所と読む順は[設定](configuration.md)にまとめました。どれか1つでも欠けると、ログインは使えず、機械の鍵だけで動きます。起動したときに、そのことを表示します。`warifuri config` でも、ログインが使えるかと、足りない項目を確かめられます。

GitHub には、ログインの名前と ID を読む以外の権限を求めません。読んだら、GitHub のトークンは捨てます。ハーネスが受け取るのは warifuri が出すトークンです。1時間で切れ、30日もつ更新用のトークンで取り直します。更新を続けても、最初にログインしてから90日たつと切れるので、そのときはログインし直します。どちらも許可の画面で選んだデバイスに結びつき、MCP の口では、機械の鍵と同じように、どのデバイスからの呼び出しかを表します。つないだアプリの一覧は `warifuri oauth clients` で見られ、あるアプリのトークンをすべて取り消すには `warifuri oauth revoke <client_id>` を使います。機械をなくしたときは `warifuri key revoke <デバイスの名前>` を使います。そのデバイスの鍵と、そのデバイスで GitHub からつないだログインが、まとめて切れます。取り消したデバイスの名前は、許可の画面で選べず、新しい名前としても使えません。

ログインのあとにブラウザを戻す先は、アプリが登録のときに名乗ります。warifuri が受けつけるのは、その機械の中(`localhost`、`127.0.0.1`、`[::1]`)か、`https` の決まった先だけです。決まった先は `claude.ai` と `claude.com` で、`WARIFURI_REDIRECT_HOSTS` にカンマ区切りで足せます。許可の画面には、アプリの名前と並べて戻り先を出します。アプリの名前はアプリが自分で名乗ったものなので、戻り先のほうで確かめてください。

### 届かないとき

台帳に届かないときも、作業は止めません。着手の確かめのフックは、台帳に届かなければ通します。エージェントは、届くようになったら、届かなかったあいだの作業を登録して閉じます(指示書のひな形にそう書く)。登録し忘れたものは、あとで人が `stale` や一覧を見て拾います。

## 置き方と入れ方

### 置き方

| 使い方 | おすすめの置き場 | 口 |
|---|---|---|
| 試す | 自分の PC | `localhost` |
| 本気で使う | VPS か、家の使っていない PC | VPS は HTTPS で直接受ける。家の PC は Tailscale(中だけ、または Funnel で外から) |

本気で使うときは、つけたままにできる機械に置きます。秘書の毎晩の仕事は、その時間にサーバーが動いていないと走らないためです。独自ドメインは要りません。外に出す置き方では、warifuri のログイン、機械の鍵、差し込みが開ける口が、守りのすべてになります。

Tailscale の Funnel や Cloudflare Tunnel のように、同じ機械のトンネルを通して外から受けるときは、`warifuri serve` に `--trust-proxy loopback`(または `WARIFURI_TRUST_PROXY`)を付けます。付けないと、どの呼び出しもトンネルから来たように見えて、ログインの口の回数の制限を、知らない人とも分け合うことになります。トークンの口は、どのアプリからの呼び出しかで回数を数えるので、知らない人が叩いても、自分のアプリの更新は止まりません。

台帳が受ける口は、MCP と HTTP API です。Web 画面のように自分の口を持つ差し込みは、何の口をどこに開けるかを、その差し込みの説明に書きます。

### 入れ方

```bash
npm install -g <パッケージ名>
```

| コマンド | すること |
|---|---|
| `warifuri init` | データのフォルダを作り、設定ファイル `warifuri.env` のひな形と空の `secrets.env` を置く。あるファイルは書き換えない。このあと、GitHub のログインの設定、最初のプロフィール、秘書を入れるか、常駐の登録(Linux は systemd、Mac は launchd、Windows はタスク スケジューラ)も対話で聞くようにする |
| `warifuri config` | すべての設定の値と、それをどこから読んだかを出す。秘密は伏せる |
| `warifuri serve` | サーバーを動かす |
| `warifuri connect` | 使う機械で、ハーネスに登録する |
| `warifuri key add` | デバイスの機械の鍵を発行する |
| `warifuri oauth clients` / `warifuri oauth revoke` | GitHub でログインしてつないだアプリを一覧する、そのトークンを取り消す |
| `warifuri backup` | 台帳とプロフィールと設定を日付つきで写す。直近7日分を残す |
| `warifuri pack` / `warifuri init --from` | 別の機械に引っ越す |

### データのまとめ方と引っ越し

台帳、プロフィール、設定、秘密は、サーバーの機械の1つのフォルダ(既定は `~/.warifuri/`)にまとめます。ほかの機械には写しを持ちません。サーバーの機械に固有の値(URL、ポート、データの場所、GitHub のログインの設定、ログインしてよい人、時間帯、報告の時刻、秘書のハーネス、差し込みの設定)は、1つの設定ファイル `warifuri.env` に集め、コードには書きません。秘密だけは、同じフォルダの `secrets.env` に分けます。項目の一覧と読む順は[設定](configuration.md)に書きました。warifuri は git を使いません。変更の履歴は台帳の記録と毎日の写しで持ちます。フォルダを自分で git にしたい人は、そうしてもかまいません。

引っ越しは3段です。

1. 古い機械で `warifuri pack`。台帳を安全に写し、フォルダを1つのファイルにまとめる。秘密を入れるかは聞く。
2. 新しい機械で `warifuri init --from <ファイル>`。設定ファイルを上から1項目ずつ「このままか、変えるか」確かめ、足りない秘密と常駐の登録を聞く。最後に、GitHub の OAuth App の戻り先を新しい URL に直すよう示す。
3. 使う各機械で、ハーネスの登録を新しい URL に付け替える(`warifuri connect --url <新しい URL>` か、ハーネスでの登録のし直し)。

秘書が使うハーネスのログインは、運ばずに新しい機械でし直します。

## 差し込み

### 用意する差し込み

差し込みを1つも入れなくても、核は台帳として動きます。

| 差し込み | やること | 要るもの |
|---|---|---|
| スケジュール | 人の空き時間を探してブロックを置く。習慣を先に置き、上限を守る | 個人の事実(生活、場所と移動、上限) |
| カレンダー | 固定の予定を読み、スケジュールを専用のカレンダーに書く | Google の接続 |
| 秘書 | ゴールが期日に間に合うかを毎晩見て、段に従って組み直しや閉じ忘れの処理をする。受け箱を週に1回整理する | サーバーの機械で動くハーネスと、使う人が用意した資格情報 |
| 窓口: Web 画面 | スケジュール、台帳、流れ図、秘書の段を見て、秘書と話す。人の時間を使うゴールの期日を確かめる | なし(warifuri のログインを使う) |
| 窓口: Discord | 秘書と話し、報告を受け取る | Discord のボット |
| 機械: 監視 | サーバーの様子を答える | Prometheus など |
| 機械: 作業用ブラウザ | 調べものを代わりに見に行く | ブラウザを動かす VM か PC |
| 機械: 実装用の手 | コードの直しを、隔離した機械で書いてテストする | 専用の VM |

秘書を入れるときの最小の形は、核にスケジュール、秘書、Web 画面を足したものです。外のサービスで必ず要るのは、GitHub のログインの設定だけです。カレンダーと Discord は、あとから足せます。秘書を入れず、エージェントが `free_time` と `book` を呼ぶだけの使い方もできます。

作業用ブラウザと実装用の手は、立てる手間も危うさも大きいので、warifuri には入れません。個人の差し込みとして書く例を示すだけにします。ほかは warifuri の差し込みとして用意します。

### 秘書の差し込み

秘書は、サーバーの機械で、ハーネスのセッションとして動きます。会話の常駐(Web 画面や Discord からの話しかけに答える)と、定時の仕事(毎晩の組み直し、見張り、毎日の報告、週に1回の受け箱の整理)があります。どちらも、ほかのエージェントと同じ MCP の道具で台帳を読み書きします。秘書は、サーバーの機械のデバイス `secretary` の機械の鍵でつなぎ、記録には秘書として残ります。

秘書の差し込みは、ハーネスのコマンド(既定は改変していない `claude`)を起こすだけにします。ハーネスへのログインは、使う人がサーバーの機械で自分で行い、warifuri はその資格情報を読みも運びもしません。ほかのハーネスを秘書の頭に使うときは、各社の規約に合わせて API キーで使います。

秘書が閉じ忘れの証拠にするのは、台帳の記録(持つ、`next`、変更)だけです。秘書はサーバーの機械にいるので、使う機械の中のファイルは見ません。

### 差し込みの形

warifuri が用意する差し込みも、使う人が自分で書く差し込みも、同じ形にします。差し込みが出せるものは次の4つです。

| 出せるもの | 例 |
|---|---|
| MCP の道具 | 監視の `server_status`、作業用ブラウザの `browse` |
| 定時の仕事 | 毎晩の組み直し、10分おきの見張り |
| 秘書への説明 | その差し込みの道具をいつどう使うか。秘書の指示書に足される短い文 |
| 設定の形 | その差し込みが読む設定の項目と、既定値 |

差し込みが台帳やプロフィールや設定に触れるのは、核の道具と API からだけです。期日や完了の条件の決まりは、差し込みからも外せません。ほかの差し込みを使うときも、直接は呼ばず、MCP の口に出ている道具を通します。

差し込みはどこに置いてもかまいません。warifuri の `plugins/` の中、手元のフォルダ、npm のパッケージのどれでも、`plugins.yaml` に書けば読み込みます。差し込みは使う人が信じて入れるコードなので、足す道具、外への通信、定時の仕事を説明の欄に書かせ、入れるときに使う人へ見せます。

### バニラと個人の拡張

```
warifuri(公開。手を入れずにそのまま使える)
   ▲ 依存する(写して改造はしない)
個人の差し込み(使う人の手元。要る人だけ)
   └─ 自分の環境に合わせた機械など
```

warifuri は、設定を書くだけで動くようにします。自分の環境に合わせたいことは、warifuri を写して改造せず、設定と個人の差し込みで行います。こうしておけば、warifuri を新しい版にしても個人の部分はそのまま残ります。

個人の差し込みのうちほかの人にも使えそうなものは、固有の語を設定へ出してから warifuri に戻します。核を変えないとできないことは、個人の側で抱えず、warifuri への変更として出します。

## プロフィール

プロフィールは、サーバーの設定フォルダの中に、1つずつフォルダを持ちます。フォルダの名前(研究、仕事など)は使う人が付けます。

```
profiles/
  研究/
    profile.yaml     既定(人が主導か、スケジュールの色、stale の日数)
    people.md        この領域の人
    knowledge.md     決まりと事実
    knowledge/       知識が長くなったときに話題ごとに分けたもの
    procedures/      手順。1つの手順につき1ファイル
    inbox.md         受け箱。エージェントの気づきを、秘書が整理するまで置く
```

knowledge.md がおよそ200行を超えたら、話題ごとに `knowledge/` に分けます。秘書がいれば秘書が週1回の整理のときに分け、いなければ人が分けます。プロフィールが1つの人は、フォルダも1つです。最初は people.md と knowledge.md だけでも動きます。

## 使う人が書く設定

サーバーの設定フォルダに置きます。書くのは、人か、`profile` / `settings` の道具を使う秘書です。

| ファイル | 中身 |
|---|---|
| `warifuri.env` | サーバーの機械に固有の値(上の節) |
| `principles.md` | 原則の書き換え。秘書とエージェントへの指示として配られる |
| `profiles/` | プロフィール(上の節) |
| `life.md` | 生活の前提と、予定の固さ |
| `places.md` | 場所と移動時間の表 |
| `habits.yaml` | 最初に入れる繰り返しの予定。台帳の習慣の表に入り、あとは `habit` の道具で直す |
| `limits.yaml` | 1日の上限、ブロックの区切り、置ける時刻 |
| `plugins.yaml` | 入れる差し込み |
| `secrets.env` | 秘密(GitHub の OAuth App の Secret など)。本人だけが読めるようにする |

名前、ドメイン、プロフィールの名前は設定から読み、コードには書きません。置き場のディレクトリの道は、台帳の置き場の表に持ちます。秘書を入れた場合は、最初の会話で秘書が life.md、places.md、`profiles/`、habits.yaml を一緒に作ります。設定のひな形は、架空の人の例として `examples/` に置き、写して書き換えれば動く形にします。
